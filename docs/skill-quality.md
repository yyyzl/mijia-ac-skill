# Skill 编写与验收约束

本文件约束本仓库的 `skills/mijia-ac-control`，依据 `writing-for-agents` 和 `yao-meta-skill` 的方法整理。目标是可共享、可维护的 Library 级能力，不以文件数量、篇幅或自评分证明质量。

## 能力与交付契约

- **负责**：读取目标空调状态；按明确意图预览、上调或下调设定温度；授权后开关机或设置已核验的模式。
- **排除**：手机/账号通用客服、硬件采购、Codex 历史查询、ESP32 烧录、室温测量、自动恒温与无人值守联动。
- **输出契约**：说明目标配置、请求动作、执行/预览状态、相关回读、结果是否匹配、可能已发生的副作用、尚缺的物理证据。设定温度与室温分开表述。
- **物理操作边界**：明确授权、明确设备、有限动作、独立回读。关机情况下，可能启动设备的设温或模式操作须额外获得开机许可。

## 文档结构

1. description 承载独立触发分支与必要排除项；用正例、反例、近邻例检验，而非堆同义词。
2. SKILL.md 保留共同执行骨架、安全默认和输出契约；每一步给可检查的完成条件。
3. 仅首次安装、平台差异、模式适配、故障诊断等分支放入 references；每个引用写清读取条件。
4. 参数与实现以 `--help`、配置 schema 和 wrapper 为真源。文档保留流程理由与陷阱，不复制大段实现或重复另写控制脚本。
5. 同一规则集中维护；新增文件必须消除当前执行歧义。入口保持精简，以实际上下文检查结果判断，不为治理标签扩写正文。
6. SKILL.md 使用正确的顶层 name、description、version、author、license、platforms；Windows 和 macOS 均为必需平台。

## 可复核证据

- 触发集包含中文与英文的正例、反例和近邻请求；description 变化后重新执行触发检查。
- 输出场景覆盖相对调温、纯预览、关机未授权、回读失败、模式副作用、把设定温度误当室温等风险；验证动作与结果，不只匹配一句安全口号。
- 继续用 fake runner 验证控制代码，用真实子进程验证安装入口；fixture 明确标为 fixture。静态评分、记录式样例与真实模型执行分别标注，不互相冒充。
- 按用途运行 Yao 可执行的结构、资源边界、上下文、触发、IR、输出、信任及打包检查；不引入未请求的客户端适配器。工具无法运行时记录实际错误和 `missing evidence`，用可行的独立检查补足，不伪造整套通过。
- Windows、macOS（并保留 Linux）的 CI 必须实际执行；本机 Windows 结果、远端系统结果、真实账号/设备效果分别报告。
- 发布前检查候选源码、许可证、上游固定提交和 SHA256。哈希同时匹配工作树与 Git 暂存/新检出内容，防止换行转换破坏完整性。
- 仅发布经过人工审查、无私有路径和账号内容的源码与评测材料；本地评测报告和真实设备日志默认不进入 Git。

## 本次方法工具的已知限制

本机 Yao 统一 CLI 在导入 `fcntl` 时失败（Windows 缺少该 POSIX 模块）。目标空调 skill 的跨平台能力与该评测引擎的兼容性分别判断；优先调用可在本机运行的独立检查器。Yao 安装目录保持只读，不为绕过检查而伪造 `fcntl`、输出或模型/硬件证据。
