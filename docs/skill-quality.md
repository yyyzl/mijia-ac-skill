# Skill 质量约束

本项目将 CLI 和 Skill 分开：CLI 负责参数校验、精确设备定位、写入与独立回读；Skill 负责理解请求、调用 CLI、解释结果。Skill 的文字不能代替 CLI 的强制检查。文档写法参考 `writing-for-agents` 和 `yao-meta-skill` 的分层与证据方法。

## 读者与文件职责

| 文件 | 主要读者 | 应回答的问题 |
| --- | --- | --- |
| `README.md` | 第一次接触项目的人 | 能做什么、适用条件、如何安装和走通首次使用 |
| `skills/mijia-ac-control/SKILL.md` | 已装载 Skill 的 Agent | 何时触发、需要哪些输入、如何执行与停止 |
| `skills/mijia-ac-control/references/` | 遇到首次准备、模式适配或故障的 Agent | 该分支的具体做法和完成条件 |
| `DESIGN.md`、本文件与评测说明 | 维护者 | 实现边界、变更依据和证据类型 |

公共执行路径保持短而完整。CLI 参数以 `--help` 和实现为准；README 给可走通的例子，Skill 给动作选择与安全条件，避免在多处复制一整套参数说明。

## 行为边界

- 查询只读 `on`、**设定温度**和原始 mode 值；相对调温先读当前设定值，再计算绝对目标。
- 写操作默认预览，实际执行需要针对本次动作的明确要求；关机设温或切模式还需要明确开机许可。
- 写后依据 CLI 的独立回读报告结果。失败停止，并指出可能已经发生的变化；不自动重试或回滚。
- 设备属性、范围、步长和模式枚举由用户在本机按 spec 核对；缺失时停止，不猜测。
- 公开材料使用无真实设备绑定的例子。配置、授权文件、完整设备清单、私人路径和本地报告保留在仓库外。

## 验证标准

1. `description` 覆盖状态、设温、开关、模式四类请求，并用中英文正例、反例和相近请求检查触发。路由变化须复跑触发评测。
2. Skill 每个执行阶段有可判断的完成条件。预览、关机无开机许可、回读失败、相对调温与设定温度/室温混淆都要有离线场景。
3. 测试只使用 fake runner；真实子进程测试限于 `--help`。记录式 fixture、静态检查、模型执行和真实设备效果分别标注，不互相冒充。
4. 发布前审查工作区、暂存区和包内文件，运行测试、公开树检查及上游完整性核对。`gitignore` 不等于泄密检查；工具结果也不能代替人工检查。

具体命令和现有证据缺口见 [评测说明](../skills/mijia-ac-control/references/evaluation.md)。
